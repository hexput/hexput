- (change) Post-final amendment during sprint planning (2026-09-18): FR-26 (optional static check) needed a structural home. Added `check/` to the Structural Seed as a twelfth module and AD-8 to bind it. AD-8's job is preventing the three submission paths (Direct Execution, CodeRegister, Plugin registration) from each growing a partial checker that disagrees with the others -- the same drift AD-3 prevents for enforcement. Key rules: `check/` is a pure entry point (AST + callable-name set + policy -> findings), never executes, never reaches rpc/ or enforce/, holds no state; invoked once per submission path, and notably NOT on CachedExecutionStart (a registered script is checked at registration, so the hot path pays once); mode read from session/'s live Config per AD-5, never snapshotted; findings reuse port/'s error shape. Explicitly advisory -- passing the check never grants a capability or offsets a budget charge, which stays enforce/'s alone via the Executor (AD-3). The Deferred entry for tree-sitter/LSP was updated to note the language server consumes check/ as a library, which is why the module is pure and daemon-independent. Frontmatter gained `amended:` and FR-26 in binds; spine was already status: final.

- (decision) Framed the crate split as a genuine architectural strengthening, not just a build-layout preference: several ADs (AD-1, AD-3, AD-4, AD-5, AD-8) state "only X may reach Y directly" rules that previously lived in code review under one crate's module tree. Under the crate graph the same rule becomes Cargo's own dependency graph -- e.g. AD-3's "no path reaches enforce/ except through exec/" is now literally true because only the hexput-exec crate lists hexput-enforce as a dependency; hexput-rpc, hexput-plugin, hexput-script physically cannot import it.
